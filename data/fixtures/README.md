# Fixtures — synthetic software-regression data

> ## ⚠️ THIS DIRECTORY CONTAINS NO REAL MARKET DATA
>
> Every file here is **deterministically generated synthetic data**. Numbers
> derived from these fixtures are **software-regression** results. They measure
> whether the code still behaves the same way — **not** whether any model can
> forecast real markets.
>
> **Do not** copy metrics produced from these files into a report, a model card,
> a README, or a claim about forecasting accuracy.

## Why synthetic

An earlier version of this fixture was derived from Yahoo Finance data obtained
through `yfinance`. That data's redistribution and model-training terms were not
cleared by this project, so it could not be committed. Replacing it with a
deterministic synthetic series removes the licensing question entirely while
keeping every property the regression tests actually depend on:

- a fixed, hash-pinned input;
- realistic session spacing on a real exchange calendar;
- regime-switching volatility and volume–volatility coupling;
- a five-session target week with known actuals.

The fixture is a **CSCO-like** series, not CSCO. It is named to resemble the
ticker only because the benchmark under test is the historical CSCO
retrospective; no CSCO observation appears in it.

## Integrity contract

The loader (`research/ndx100/csco_fixture.py`) enforces all of the following and
raises `FixtureIntegrityError` on any violation:

1. The manifest exists and is valid JSON.
2. `evidence_role == "synthetic_software_regression_fixture"`.
3. `certification_eligible is False` — this fixture can never certify a model.
4. `canonical_file` identifies the canonical CSV.
5. `fixture_id` and `manifest_version` match the loader contract.
6. `canonical_sha256` is lowercase hex and matches the **hash pinned in code**,
   not merely the hash recorded in the manifest.
7. The CSV's SHA-256 is verified **before** it is parsed.
8. Size, row count, date range, column set, and value sanity all match.

Points 6 and 7 matter: verifying only against the manifest would let an attacker
who can edit both files substitute data undetected. The hash pinned in source
code is the trust anchor.

## Regenerating

Regeneration is a deliberate act, not a side effect:

```bash
PYTHONPATH=. python -c "
from research.ndx100.csco_fixture import generate_synthetic_csco_fixture
generate_synthetic_csco_fixture(write=True)
"
```

Regenerating changes the canonical hash, which invalidates the pinned
`EXPECTED_CANONICAL_SHA256` and every golden value. The test suite will fail
until those are deliberately updated. That failure is the intended behaviour.

## Non-goals

This fixture is **not**:

- certification-grade market evidence;
- a basis for claiming any model beats any baseline on real data;
- suitable for tuning model hyperparameters;
- a substitute for the Phase 6 full point-in-time benchmark.
